# AttnRes：用层间 Attention 替代 Residuals

> [!abstract] 一句话总结
> 这篇文章介绍 Attention Residuals（AttnRes）：把 Transformer 里原本固定的残差连接，推广成“跨层状态的加权聚合”，也就是把 **Residual 看成一种特殊的层间 Attention**，再进一步做成既有效又可训练/可推理的版本。

---

## 我为什么觉得这篇值得收进知识库

它不是单纯在讲一个“小改结构”的技巧，而是在改一个更底层的问题：

**Transformer 每一层到底应该如何接收历史层的信息？**

传统 Residual 的答案很朴素：
- 上一层输出直接加回来
- 或者换不同的 norm / gate 形式继续加

AttnRes 的答案更激进：
- **不把层间连接当固定加法，而当成一类可学习的信息路由机制**
- 让当前层从所有历史层中，自适应选择该看谁、看多少

这相当于把“序列上的 Attention”扩展成“深度方向上的 Attention”。

---

## 一、核心观点

### 1. Residual 可以看成层间 Attention 的特例

文章的关键出发点是：

- Residual 并不一定非得是“当前层 + 上一层”这种固定形式
- 从递推展开的角度看，它本质上是在对过往层的状态做一种 **等权聚合**
- 既然可以等权聚合，那自然也可以推广成 **加权聚合**

于是就得到 AttnRes 的萌芽：

> 将跨层状态的固定求和，改成由权重控制的加权求和。

这一步很重要，因为它把“残差连接”从工程习惯，提升成了一个统一视角下的结构设计问题。

### 2. HC / mHC 也能放进这个统一视角里

文章还回顾了：
- HC（Hyper-Connections）
- mHC（DeepSeek 对 HC 的改进）

作者证明：

**HC / mHC 其实也可以理解成层间 Attention 的一种形式。**

也就是说：
- Residual
- HC / mHC
- Full AttnRes
- Block AttnRes

这些看起来很不一样的结构，其实都能落到“深度方向的信息聚合矩阵”这个统一框架里。

这点很有价值，因为它给了一个更高层的理解工具：

> 以后看类似架构，不要只看“有没有残差 / 有没有 gate / 有没有扩维”，而要看：
> **它到底怎么在层之间分配信息权重。**

---

## 二、AttnRes 到底做了什么

### 1. Full AttnRes：先做“完整跨层连接”

作者最早的版本很朴素：

- 用一个**静态可训练向量**作为 Query
- 各层状态作为 Key / Value
- 在深度维度上做 Softmax Attention

也就是：
- 当前层不是只接前一层
- 而是从历史层里按权重汇总信息

有意思的是，这个设计一开始并不复杂，甚至可以说有点“先试试再说”，但实验效果已经明显优于普通 Residual。

### 2. 终版改进：给 K 加 RMSNorm

团队后面试了更复杂的方案，结果发现大多不如简单版稳定。

最后比较有效的改动是：
- 给 Key 额外加一个 RMSNorm

这很像很多架构演化里的真实规律：

> 真正能进主线的，不一定是最花哨的设计，而是**简单、稳定、收益明确**的设计。

### 3. 静态 Q 是工程落地的关键

作者特别提到，静态 Query 的设计后来成了推理可行性的关键点。

因为 Query 不依赖具体输入，某些跨层注意力项可以提前处理，给推理系统留出优化空间。

这说明 AttnRes 不是“理论上有意思但工程没法跑”的东西，团队从一开始就在往：
- 训练可行
- 推理可行
- Infra 可接住

这个方向收敛。

---

## 三、为什么 Full 版不够，最后转向 Block 版

Full AttnRes 虽然效果好，但问题也明显：

- 跨所有层做密集连接，开销大
- 训练通信和显存压力高
- 大模型场景下不够现实

于是团队继续往下做，得到 **Block AttnRes**。

### Block AttnRes 的核心思路

不是简单“稀疏化”，而是：

- 先把层分成若干个 block
- block 内做压缩（求和聚合）
- block 之间再做 attention
- embedding 层单独保留成一个 block

作者对这个设计的判断很有启发：

> 对 AttnRes 来说，**压缩比稀疏更重要**。

原因是：
- Residual 本身已经是非常强的 baseline
- 它等价于“所有历史状态都参与、只是权重固定”
- 如果你用滑窗等稀疏方式直接丢信息，可能连 Residual 这个特例都覆盖不了

所以，想超越 Residual，至少形式上要能“包住”它。

这也是为什么：
- Sliding Window Attention 这类方案效果反而不好
- Block 压缩 + 跨块 attention 更合理

### 实际收益

文章里给出的量级大意是：
- 额外开销约 **5% 以内**
- 换来大约 **25% 的收益**

如果这个量级在更多任务和规模上成立，那就不是“小修小补”，而是很值得关注的架构变体。

## 四、这篇文章最值得记住的 5 个点

### 1. Residual 不是唯一合理的层间连接
Residual 只是一个历史上非常成功、非常稳定的默认答案，不代表它是结构设计的终点。

### 2. “Depth Attention” 这个想法不新，但“做成可落地版本”很难
作者也坦承：2026 年再说 depth attention，本身不是新概念。

真正有价值的地方是：
- 如何让它替代强 baseline（Residual）
- 如何兼顾训练效率和推理效率
- 如何真正推进到足够大的模型规模

也就是说，新意未必在概念，而在**可用性闭环**。

### 3. 简单设计往往比复杂设计更容易成为主线
第一版静态 Q 的直觉式设计，最后反而变成工程落地的关键。

这提醒我：
- 架构创新不只看表达力
- 还要看可实现性、可优化性、系统友好度

### 4. 统一视角比单点技巧更重要
把 Residual、HC/mHC、AttnRes 放进同一个矩阵/attention 视角后，很多“看似分裂的架构改动”就能被重新组织起来。

这是比单篇论文结论更值钱的收获。

### 5. 好的结构改进，要至少覆盖旧 baseline 的能力边界
如果一个新结构连旧结构能表达的特例都装不下，那它大概率不会稳定胜出。

这条判断标准很实用，之后看别的架构改动也能直接拿来用。

---

## 五、我的理解：这篇文章本质上回答了什么问题

我觉得它真正回答的是：

> **模型深度增加之后，历史层的信息到底应该如何被“记住”和“重新分配”？**

Residual 的做法是：
- 简单保留
- 稳定传递

AttnRes 的做法是：
- 不只保留
- 还要在深度维度上重新选择和组合

如果把 sequence attention 理解成“token 与 token 之间的信息选择”，那 AttnRes 可以理解成：

> **layer 与 layer 之间的信息选择。**

这是一个很自然、也很有潜力的方向。

## 六、对后续阅读 / 研究的启发

### 可以继续追的问题

1. **AttnRes 对不同规模模型的收益曲线如何？**
   - 小模型有效，不代表大模型同样成立
   - 需要看 scaling behavior

2. **它对不同任务类型是否稳定？**
   - 预训练
   - 指令微调
   - 长上下文
   - 推理型任务

3. **Block 划分是否还能自适应？**
   - 现在是固定 block
   - 后续也许可以学习式分组

4. **能否与 MoE、线性 attention、状态空间模型结合？**
   - 如果深度方向也做信息路由，和 token 路由会不会出现更有意思的组合

5. **可解释性会不会更强？**
   - 因为注意力矩阵天然可视化
   - 可能能更直观看到模型“依赖哪些历史层”

---

## 七、如果只记住三句话

1. **Residual 可以被重新理解为“层间 attention 的一个特例”。**
2. **AttnRes 的价值不只是提出想法，而是把它做成了大模型可训练、可推理的版本。**
3. **从 Full 到 Block 的过程说明：结构创新要想进主线，必须同时解决效果、稳定性和系统成本。**
